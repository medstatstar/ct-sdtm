> **档位：B（需保密输入 · 本地处理 · 不出域）** ｜ 生命周期阶段：⑤ 数据管理（转换侧）

将申办方 raw 数据按 **CDISC SDTMIG v3.4**（FDA 自 2025-03-15 强制）映射为合规 SDTM 数据集：应用受控术语校验、执行合规检查，并准备可递交的 XPT v5 + Define-XML v2.1 源数据；同时支持反向 CRF 字段匹配、SDRG/ADRG 审阅指南草稿与合成测试数据生成。**全程本地处理，保密数据不出域。**

---

## 本技能的使用方式

本技能为 **B 档技能**：技能包**不对外公开发布**（仅公开本说明等白名单文件，定制 / 本地部署请联系作者），因此下面的两种使用方式是**全功能版与在线共享版**的关系：

1. **对话提示词（全功能）**：在 WorkBuddy 或其他AI智能体中加载本技能，用自然语言描述需求即可；技能在本地执行真实映射并回报结果，本说明提供的全部案例与能力均以此方式完整体现。
2. **工作台 UI（免安装使用）**：直接访问 ct 系列统一网页入口 **https://ct.medstatstar.com** ，即可在浏览器中使用公开提供的功能，所有用户共享每日总免费额度，但数据需要外发到coze服务器处理，请用户自行评估和控制风险。

## 适用人群

`ct-*` 临床试验技能家族专用于解决临床试验全生命周期的各类需求，ct-sdtm 主要面向需要**把原始采集数据转换成合规 SDTM 数据集**的三类人群：

- **各制药企业的临床试验从业者** —— 申办方、CRO，以及数据管理 / 统计编程 / 医学 / 注册等角色：完成 raw → SDTM 映射、受控术语应用与递交前合规检查；
- **在医疗机构中设计、管理临床试验项目，或参与临床试验研究实务的医护人员**：核对 CRF 字段与 SDTM 变量的对应关系，理解数据标准化流程；
- **希望系统学习临床试验知识的医学专业学生**：学习 SDTMIG v3.4 域结构、受控术语应用与 Define-XML 递交规范。

> 难度层级：★ 基础 / ★★ 进阶 / ★★★ 专业。每个案例末尾「🖥️ 工作台」指向对应视图与操作要点。注意：网页方式下「映射」结果默认不落盘——结果区即产物清单，点「全部打包下载」才会拿到压缩包。

## ★ 基础用法

### 案例 1 · 一键映射整目录原始数据

**你这样说：**
> 帮我把 data/raw 目录下的临床试验原始数据映射成 SDTM 标准数据集。

**助手会这样回（示意）：**
> 已读取 data/raw，识别到 5 个域（DM / AE / LB / VS / EX），写出 sdtm_dm.csv（12 受试者）、sdtm_ae.csv（38 条不良事件）、sdtm_lb.csv（156 条）、sdtm_vs.csv（84 条）、sdtm_ex.csv（60 条）。映射期自动完成三件事：
>
> 1. 值级路由补全单位（如 VSTESTCD=DIABP → VSSTRESU=mmHg）；
> 2. 逐变量记录映射证据链（来源列 + 规则编号）；
> 3. 跑合规规则集，共 2 个 issue。
>
> 无 Error，可直接交付下游 ct-adam。

**🖥️ 工作台：**
> 进入「映射」视图 → 上传原始文件（CSV/TSV）→ 每个文件卡片下拉选「目标域」→ 域选择网格勾选 → 点「映射」，结果区给出域 / 行数 / Issues 与产物清单。

### 案例 2 · 先预览再落地（安全预览）

**你这样说：**
> 先别写文件，只预览一下各域会映射多少行、有多少个 issue。

**助手会这样回（示意）：**
> 预览模式（未生成任何文件）：DM 12 行 / AE 38 行（1 issue）/ LB 156 行（1 issue）/ VS 84 行 / EX 60 行。合计 350 行，2 个 issue（均为 Error）。预览与正式映射走同一处理路径，行数与 issue 数完全一致。确认无误后说「开始映射」即可写出。

**🖥️ 工作台：**
> 「映射」视图点「预览映射」可先看域 / 行数估算（不落盘）；正式「映射」本身也不落盘，只在结果区给出产物清单，点「全部打包下载」才会拿到压缩包。

### 案例 3 · 值级映射路由（自动补单位）

**你这样说：**
> 映射生命体征时我只有检验代码和结果，没有单位列，能自动补上吗？

**助手会这样回（示意）：**
> 已启用值级映射路由：按内置值级规则的条件路由——唯一值规则自动填充，多值规则仅提示不臆造。本次 VSTESTCD=DIABP/SYSBP → VSSTRESU 自动填 mmHg（值级唯一）；VSTESTCD=TEMP 的候选为 C/F（多值）→ 记提示请人工确认，未自动填充。两道防护：占位符值集不填；结果类变量（原始值 / 标准值 / 标准值数值）不做值级填充。

**🖥️ 工作台：**
> 值级路由与受控术语校验均为映射引擎内置，勾选「受控术语校验」即生效，无需额外操作。

### 案例 4 · 生成中英文双语标签数据集

**你这样说：**
> 给我一份带中文变量标签的版本，方便非技术同事核对。

**助手会这样回（示意）：**
> 已启用双语输出。每个 SDTM 数据集新增 `<变量>_LABEL_ZH` 列，如 USUBJID→受试者唯一标识、AETERM→头痛。常见变量机器初始化中文标签覆盖率约 87%，个别专业限定符若为空可后续补全。XPT 的变量标签另走 ASCII 英文标签（XPT v5 为 ASCII 传输格式，中文标签仅用于 Define-XML 双语字段）。

**🖥️ 工作台：**
> 「映射」视图默认勾选「双语标签输出」，产物即带 `_LABEL_ZH` 列。

### 案例 5 · 自定义列名映射（适配 EDC）

**你这样说：**
> 我 EDC 导出的列名不一样，gender→性别、adv_event→不良事件，放了个列名映射文件按它映射。

**助手会这样回（示意）：**
> 已加载你的列名映射文件作为列别名覆盖：gender→SEX、adv_event→AETERM、ae_start→AESTDAT。映射完成 0 个必填缺失，未覆盖列走默认规则。映射证据链中这些变量会标注来自你的规范（区别于内置别名表），可据此核对哪些列来自你的 EDC 规范。

**🖥️ 工作台：**
> 内置别名表已覆盖常见 EDC 列名；完全自定义的列名请经本地全功能方式提供映射文件后映射。

## ★★ 进阶用法

### 案例 6 · 受控术语校验并列出违例（含近似值建议）

**你这样说：**
> 映射时顺便做受控术语检查，把 SEX、AESEV、RACE 取值不符合受控术语的都列出来。

**助手会这样回（示意）：**
> 已完成受控术语校验。发现 3 处违例：AESEV="SEVRE"（封闭码表，是否指 'SEVERE'？）；AESEV="MODERAT"（是否指 'MODERATE'？）；RACE="Han"（可扩展码表，仅 Notice 不阻断）。封闭码表脱靶判 Error，可扩展码表新值判 Notice——与受控术语可扩展性规则一致。空值不判违规（缺失值由 Required 规则负责）。

**🖥️ 工作台：**
> 「合规检查」视图上传数据集 → 选术语版本 → 点「术语校验」；或在「映射」视图底部的「受控术语版本」区对映射产出做术语校验。

### 案例 7 · 术语版本切换与多版本核对

**你这样说：**
> 我想确认这份数据在 SDTMIG v3.4 (2022) 术语表下是否合规，也想知道切换术语版本后结论会不会变。

**助手会这样回（示意）：**
> 当前激活术语版本：SDTMIG-3.4-2022。切换术语版本后重跑校验，结论是否变化取决于该变量在新旧版本码表中的归属差异。指定未知版本时自动回退到顶层兼容术语表，不静默失败。

**🖥️ 工作台：**
> 术语版本切换条在「合规检查」视图与「映射」视图的「受控术语版本」区各有一处，切换即重跑术语校验并回报「使用版本 / 激活版本 / 校验变量数」。

### 案例 8 · 自定义校验规则包（企业规则）

**你这样说：**
> 我们公司有内部数据质量要求：USUBJID 不许含空格、事件术语不超过 200 字符、AESER=Y 时必须有 AESTDTC。能加进校验吗？

**助手会这样回（示意）：**
> 已写入自定义规则文件（条件 + 参数 + 严重级，结构与内置规则同构）。新增 4 条：USUBJID 含空格 → Warning；事件术语超 200 字符 → Warning；AESER=Y 缺 AESTDTC → Error；术语含全角标点 → Notice。规则包保存前先自检（编号冲突 / 严重级 / 条件 / 必需参数），不通过则拒绝启用，不静默跳过。规则包置空即禁用自定义层。

**🖥️ 工作台：**
> 自定义规则需在本地全功能方式配置；「映射」「合规检查」均套用该规则层，映射视图勾选「CORE / CG.MODEL 校验」即启用校验。

### 案例 9 · 反向 CRF 字段匹配（证据链版）

**你这样说：**
> CRF 设计里有个字段叫「项目 12」，标签也是「项目 12」，样本值是 M/F/U，帮我匹配到最合适的 SDTM 变量。

**助手会这样回（示意）：**
> 反向匹配结果：推荐 DM.SEX，置信度 high / 0.98。证据链：值集证据（3/3 个取值 ⊆ SEX 小闭集码表，共 4 项）+ 变量必需性（目标变量 Core=Required）。字段名与标签均无提示，纯靠**值集证据**完成决定性匹配。另可提供多字段批量匹配：值集证据、表单结构覆盖率投票（如含访视开始日期时访视序号优先归 SV）、声明式规则（可扩展）、映射质检（日期格式 / 术语取值 / 序号唯一性）同时生效。

**🖥️ 工作台：**
> 进入「反向匹配」视图，每行粘贴 `字段名,标签[,样本值1;样本值2]`，点「匹配」，结果含推荐域 / 变量 / 置信度与证据链。

### 案例 10 · 先校验映射规格再跑映射

## ★★★ 专业用法

### 案例 13 · 完整合规校验（含模型级规则）

## 三、首次使用常见问题（FAQ）

**Q：我没给映射规格，只有 EDC 导出的原始数据，能映射吗？**
A：能。分两种情况：

- 常见 EDC 列名——内置别名表自动识别，直接映射；
- 列名差异较大——提供一份列名映射文件覆盖「原始列 → SDTM 变量」即可。

**Q：原始数据支持哪些格式？**
A：CSV / TSV / Excel / SAS 数据集 / XPT / JSON 均可，自动按域识别并统一处理。

- 网页方式上传目前读取 CSV/TSV 文本；
- 其他格式请先在本地转换成 CSV，或经本地全功能方式处理。

**Q：预览的结果和正式映射一致吗？**
A：一致——两者走同一处理路径，行数与 issue 数相同；区别只是预览不写文件。

**Q：映射完成后，怎么拿到生成的文件？**
A：按使用方式分两种：

- 本地方式：产物直接写入你指定的输出目录；
- 网页方式：「映射」结果区即产物清单——各域数据集、issue 清单、定义文件与溯源文件都在里面，点「全部打包下载」即可取得压缩包，下载即取即走。

**Q：映射或校验结果能按我们的习惯调整吗？**
A：两层可调：

1. 用**列名映射文件**覆盖「原始列 → SDTM 变量」的对应关系；
2. 用**自定义规则包**增删企业校验规则（保存前自检，不通过不启用）。

**Q：中文环境下输出是中文吗？**
A：分三层：

1. 对话语言跟随你的提问；
2. 数据集可输出中文变量标签列，Define-XML 支持双语标签；
3. 注意：XPT 传输格式只支持 ASCII 英文标签，中文标签体现在 Define-XML 双语字段中。

**Q：如果数据要保密怎么办？**
A：用**本地全功能版**——零联网、数据不出域，受控术语本地内置，raw 数据与产物全程留在本机。

**Q：产物可以直接用于监管递交吗？**
A：分两部分：

1. XPT v5 + Define-XML v2.1 按可递交标准生成，但递交前须经贵方 QA 与统计编程审核；
2. SDRG/ADRG 为草稿框架（填不了的显式标记 [TBC]），不定稿、不替代审核。

## 版本基线与安全模型（B 档，最高优先级）

- **版本基线**：映射规则与受控术语一律按 **SDTMIG v3.4** + **Define-XML v2.1**，勿沿用 v3.2。
- **本地处理**：raw / 规格 / 产物均在本地；不读用户私人文件除非显式授权。
- **零联网**：默认 `network: none`；受控术语本地内置，不在线取词。
- **可溯源**：每条映射产出带规则编号 + 规格版本 + 引擎版本，运行清单即稽查轨迹等价物（对齐 CDE 2026 年第 44 号通告 ALCOA++ 原则）。
